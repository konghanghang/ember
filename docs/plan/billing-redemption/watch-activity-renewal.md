# 分组观看保号方案

> 状态：业务规则已确认，待技术设计；按用户要求暂缓实施，本轮仅保存计划
> 负责人：Ember
> 更新时间：2026-10-04

## 背景

公益套餐希望允许持续观看的用户自动延长使用期限，减少手工续期。当前套餐描述中的“观看保号”只是文案，不会自动延长权益，需要独立实现。保号应依附已有分组权益，复用多组权益与到期回退规则。

## 目标与非目标

目标：按分组配置观看保号；达到每日有效观看门槛后延长对应组权益；所有权益失效后停止 Emby 访问，但保留 Ember 登录和购买套餐能力。

非目标：观看授予新分组、自动恢复已过期权益、解除人工禁用、修改购买累加规则、叠加其他分组期限、实时到期回退。本轮不修改代码、数据库、线上配置，也不执行外部验证。

## 当前事实

- 前置方案：[套餐与分组权益改版](./plan-group-entitlements.md)；现行边界见[系统架构](../../system-architecture.md)。
- 商品通过 `Plan.planGroup/validityType/days` 发放单组权益，订单保留权益快照；用户可持有多条 `UserEntitlement`，各组独立计时，最高有效权益等级决定生效组。
- `User.planGroup/expiresAt/resourceAccessGranted` 是访问投影；分组同时决定资源库与相应限制。高等级组到期后可回退到仍有效的低等级组。
- `services/api/internal/services/entitlement/` 负责权益计算与持久化；`services/api/internal/services/system/expiry.go` 负责既有定时到期处理。观看保号尚未实现。
- Emby Server 目标版本为 4.9.3.0。播放数据源、插件版本及实际播放计时是否满足保号需求仍待核对；不能直接把排行榜聚合值视为授权依据。

## 方案设计

### 1. 已确认配置与行为

在分组管理中配置以下三项，适用于需要观看保号的分组，不硬编码某个分组名称：

| 配置 | 规则 |
| --- | --- |
| 观看保号开关 | 按组设置，默认关闭 |
| 保号时长 | 单位天，由管理员配置；讨论以 30 天为例，默认值和取值范围待定 |
| 每日有效观看门槛 | 单位分钟，默认 10 分钟，管理员可修改；取值范围待定 |

按 `CRON_TIMEZONE` 划分自然日，累计当天实际播放时长；暂停和拖动进度不能算作有效观看。用户必须已经持有目标组的未到期权益，达到门槛后才能延长该组期限。

延期规则：`新到期时间 = max(原到期时间, 有效观看时间 + 保号时长)`。

- 这是保号窗口，不按观看次数累加天数。例如保号时长为 30 天，原权益还剩 60 天时，不缩短原期限。
- 永久权益无需延期；没有目标组权益时不创建权益。
- 仅延长开启保号的对应组，其他付费组的期限保持不变；保号不能直接复用购买时的天数累加语义。
- 已过期权益不能靠观看自动恢复，需要重新购买或管理员恢复。
- “有效观看时间”的精确取值，以及一日多次达标后的计算边界，列入实现前待确认项，不在本计划中假定。

### 2. 到期与账号边界

- 沿用已有每日多个时点的定时到期检查，允许权益到期与访问投影更新之间存在调度延迟，不增加请求时重算或额外高频兜底。
- 某个组失效但仍有其他有效组时，按已有规则选择生效组并同步资源权限，不能直接封禁整个账号。
- 所有组权益均失效时，由到期任务禁用 Emby 访问，保留 Ember 登录，用户可以购买套餐恢复相应权益。
- 观看保号及购买后的访问恢复不得绕过人工账号停用或 Emby 人工禁用。
- 调度延迟不等于延长权益资格：已过期但尚能播放的情况，不能因此自动恢复已失效的权益。

### 3. 模块与数据边界

- 分组管理 API/Web：增加三项配置的读取、编辑、校验；前端必须遵守 Ember 风格，设计与交互以[前端设计规范](../../reference/web-design-guide.md)为基线。
- 播放适配层：基于核实的版本化合同提供可追溯的播放事实，负责外部时间语义转换，不直接修改用户权益。
- 权益服务：校验保号资格，执行窗口延期，处理与购买、人工延长、换组、到期任务的并发，统一维护权益记录、审计与访问投影。
- 调度层：确定统计与延期执行时机，复用现有到期处理职责；具体调度频率和与到期任务的顺序在技术设计阶段收口。
- 数据库：预计增加分组配置及必要的处理进度、幂等或审计记录；具体字段和是否新增表待设计。模型、约束变化须同步 SQL migration，不能依赖 `AUTO_MIGRATE`；已部署迁移按现行迁移规则处理。本轮不编写或执行 SQL。
- 对外字段使用 camelCase，列表响应保留 `data`；GORM 映射显式指定列名。具体 DTO/API 合同待技术设计，不先扩展支付或 Bot 接口。

### 4. 关键流程与失败处理

1. 读取开启保号的分组配置，通过核实的播放协议获取事实并映射到 Ember 用户。
2. 按全局业务时区统计每日有效观看，排除不合格及重复数据，判断门槛。
3. 在权益写入边界再次校验配置和目标权益资格，以窗口公式计算新期限，避免并发覆盖管理员或购买产生的更新。
4. 保存处理证据与延期结果，按既有权益服务维护投影；到期回退、全部失效后的禁用仍由现有到期任务承担。

播放数据缺失、协议无法确认或外部读取失败时，不能猜测观看达标或无条件续期。记录用户/分组标识、统计窗口、跳过原因和失败点，不记录凭据或完整外部响应。重试不能重复累加权益；补查与重试窗口需在技术设计中明确。

## 实现前待核对事项

以下事项尚未确认，不能作为已定规则直接编码：

1. 核对[Playback Reporting 合同](../../reference/playback-reporting-api-contract.md)及[Emby 用户策略合同](../../reference/emby-user-policy-and-item-route-contract.md)，确认插件版本、播放事实来源、权限、时间、错误及暂停/拖动语义；现有合同不足时先补参考文档。真实只读调用须另有明确授权。
2. 确定有效观看时间的取值、多设备并发去重、跨天拆分、重复/乱序/晚到数据及用户绑定变化的处理方式。
3. 确定过期前已完成观看、但到期后才被统计时的资格判断与任务顺序，保证不违反“已过期不能自动恢复”的已确认边界。
4. 确定观看适用范围：是否限定当前生效组或特定资源库，以及同时持有多个保号组时如何匹配；本轮未约定额外限制。
5. 确定配置开启/关闭或调整门槛后的生效边界、历史观看是否计入、补查窗口，以及天数的时间计算语义。所有业务日期统一使用 `CRON_TIMEZONE`，外部 UTC 时间须在边界显式转换。
6. 收口配置默认值与范围、幂等持久化方案、任务执行频率，以及失败与重试时对到期处理的影响，不擅自增加宽限期或实时兜底。

## 验证方式

本轮仅检查计划、索引、相对链接与差异格式，不执行业务测试。未来实现先用失败测试锁定状态流转；Go 外部依赖全部 mock，前端测试不依赖真实后端。

| 场景 | 验收预期 |
| --- | --- |
| 开关关闭、未达门槛、无目标组权益 | 不延期、不授予新组 |
| 当天多段实际观看刚好达标 | 按已收口的有效观看时间和窗口公式延期 |
| 暂停、拖动、跨日、多设备、重复记录 | 按核实合同统计，不能虚增有效观看或重复延期 |
| 原期限大于窗口、永久权益 | 原期限保持不变 |
| 多组权益、限时高组与长期低组共存 | 仅目标组延长，最高有效等级选择和回退正确 |
| 权益已过期但到期任务尚未执行 | 不能靠新观看恢复该权益 |
| 所有组失效后执行到期任务 | 禁用 Emby，保留 Ember 登录和购买入口 |
| 仍有其他有效组、人工禁用 | 分别保留有效组访问、保留人工限制 |
| 购买/人工延期/换组/到期任务并发 | 不丢失更新、不误恢复、不重复累加 |
| 外部失败、晚到数据、任务重试、配置变更 | 按实施前收口的规则处理，证据和失败原因可追溯 |

实现阶段在 `services/api` 执行适用的 `go test`、`go vet ./...`、`go build ./...`；在 `services/web` 执行相应测试及 `npm run build`。按影响面补 mock 合同测试、数据库并发与迁移测试。浏览器和真实 Emby 验收另行授权，不能将 mock 通过表述为外部链路已验证。
