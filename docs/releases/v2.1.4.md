# Ember v2.1.4

## 本次更新

本版本修复 Web 双架构镜像构建中 arm64 Node 依赖安装经过 QEMU 时发生非法指令异常、构建长期无法结束的问题，保留 `v2.1.3` 的排行榜和 Gateway 功能修复。

## 问题修复

- Web 的 Node 构建阶段固定使用构建机原生架构，依赖安装和静态资源编译不再经过 arm64 QEMU；静态产物分别复制到目标架构 Nginx 镜像，正式镜像仍支持 `linux/amd64` 与 `linux/arm64`。
- 依赖安装严格执行 `npm ci`，失败立即终止，删除 `npm install` 回退；构建元信息参数移至依赖安装之后，避免只更换 commit SHA 就使依赖层缓存失效。
- Web 镜像工作流增加 20 分钟任务超时，为异常安装或推送提供明确结束边界。

## 升级说明

- 相比 `v2.1.3`，本版本没有新增数据库 migration、配置项、环境变量或 Redis key，不需要额外手工执行 SQL。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- 从 `v2.1.2` 或更早版本升级时，会包含 `v2.1.3` 引入的排行榜批次迁移。升级前备份数据库，并阅读 [v2.1.3 升级说明](./v2.1.3.md#升级说明)，了解自动迁移、历史数据保留、配置来源与数据库回退边界；不能只切换旧镜像就假定完成数据库回退。
- 从 `v2.1.1` 或更早版本升级时，还需阅读 [v2.1.2 升级说明](./v2.1.2.md#升级说明)，核对 115 新增转存的明确起播许可及 STRM-only 回退边界。
- API、Web、Bot 默认镜像更新为 `v2.1.4`；API 与 Gateway 必须使用同一个 `EMBER_API_IMAGE`。已在 `.env` 或 Compose override 固定镜像的部署应同步更新覆盖值，保持既有密钥不变。
- `v2.1.3` 的 Web 正式镜像构建未完成，两次执行均在 arm64 依赖安装阶段出现 QEMU `Illegal instruction` 后被取消。请在确认本版本三个正式镜像工作流全部成功后使用 `v2.1.4`；不覆盖已推送的 `v2.1.3` Tag。

## 已知限制与验证边界

- 构建修复已完成本地验证：Web 266 项测试通过、3 项集成测试跳过，类型检查与生产构建通过；工作流 YAML、20 分钟超时、原生构建阶段、锁文件安装失败退出、静态产物跨阶段复制和目标运行架构约束检查通过。
- API、Bot 与数据库资产相比 `v2.1.3` 未变，复用同一会话已完成的 Go 全量测试、vet、build、排行榜 PostgreSQL 专项，以及 Bot 77 项测试和语法检查结果。外部依赖使用 fake / mock，不代表真实外部服务或生产验收。
- 本机 Docker daemon 未运行，未执行本地双架构镜像构建；完整镜像验收以本 Tag 的 GitHub Actions 结果为准。Nginx 运行层的 arm64 `apk` 仍可能使用 QEMU，因此保留 binfmt 初始化；本次只消除 Node 构建阶段对模拟执行的依赖。
- `v2.1.3` 发布准备时记录的 npm 全依赖审计 15 项告警仍作为独立事项，生产依赖审计为 0 项；本版本未修改依赖版本。真实 Playback Reporting 版本与筛选兼容性、播放器及生产配置的验证边界沿用 [v2.1.3 发布说明](./v2.1.3.md#已知限制与验证边界)。
