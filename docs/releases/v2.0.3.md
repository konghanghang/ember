# Ember v2.0.3

## 本次更新

本版本继续收口 `v2.0` Playback Gateway，重点完善 Emby Web 登录和图片访问、网页入口控制、运行期日志配置与播放排障能力。默认仍允许通过 Gateway 打开 Emby 网页端，已有原生客户端 API、视频和根 WebSocket 门控保持不变。

## 重点功能

- 设置中心新增“Gateway Emby 网页访问”开关，默认开启，保存后最多 5 秒生效。关闭后 Gateway 不访问上游 Emby，而是返回自包含、禁止缓存的中文友好 `404` 页面；Infuse 等客户端 API、视频、携 Token 图片和根 WebSocket 不受该开关影响。
- API 与 Gateway 的 `LOG_LEVEL` 迁移到设置中心，继续只接受 `info/debug` 并默认 `info`。API 保存后立即切换，独立 Gateway 最多在 5 秒内同步，不再需要重启；Python Bot 仍独立使用启动环境变量 `LOG_LEVEL`。

## 问题修复

- 兼容目标 Emby Web `4.9.3.0` 的登录前 query 应用元数据，严格支持 Public users、Branding Configuration 与 AuthenticateByName 的固定请求形态；Header/query 混用、外部 Token、重复或非法字段继续失败关闭。
- 认证响应旁路新增 Brotli 解码，在保持上游状态、Header 和压缩字节不变的前提下建立 Token 映射；损坏、未知编码或解码后超限仍只跳过映射，不篡改 Emby 成功响应。
- 收窄代理目标 Web 登录前语言资源、Branding CSS，以及登录后无 Token 的精确 Item Image；Backdrop Index 仅接受规范非负 int32 路径，root、修改、深层、encoded 和非法 Index 继续受保护。
- Gateway 运行期配置使用 5 秒正负缓存、并发刷新合并和错误退避，避免日志级别与网页开关逐请求查询数据库；Web 开关读取失败继续 fail-closed，日志级别读取失败则保留上一次有效值。
- Token Store 对明确可重试的幂等读取连接故障最多重试一次，并继续区分请求取消、deadline、业务拒绝和真实存储故障。

## 运维优化

- Gateway 增加 Playing、Progress 与 Stopped 的有界播放会话摘要。开始、停止、失败和失败后的首次恢复使用中文 Info 结论，正常 Progress 心跳仅在 Debug 输出，且不记录 Token、Cookie、Authorization 或完整请求体。
- API/Gateway 运行期日志级别会同步控制安全 access 摘要、GORM 参数化 SQL 与 Gateway 诊断；Debug 仍不放宽任何敏感信息保护。
- ConfigService 普通数据库配置按 key 使用 60 秒惰性 TTL 缓存，并在当前 API 进程保存成功后失效对应 key；没有跨进程主动失效或后台刷新。

## 升级说明

- 本版本不包含新的数据库 migration，不需要手工执行 SQL；最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- API/Gateway 不再读取环境变量 `LOG_LEVEL`。如果现有部署依赖 `.env` 中的 `LOG_LEVEL=debug`，升级后需要在设置中心重新选择 API/Gateway 日志级别；同一环境变量仍继续控制 Python Bot。
- `PLAYBACK_GATEWAY_WEB_ENABLED` 只存在于设置中心和 `settings` 表，不读取同名环境变量；缺少数据库记录时默认开启。
- API 与 Gateway 必须使用完全相同的 `EMBER_API_IMAGE` Tag；Compose 默认 API、Web、Bot 镜像已同步更新为 `v2.0.3`。
- 目标 Emby Web 已确认 Public users、Branding Configuration、Brotli 登录映射、Sessions Capabilities、UserSettings 与无 Index Primary 图片可取得上游成功状态；Backdrop Index 修复后的真实图片状态、完整页面资源、网页播放和登录后 WebSocket `101` 仍未实机确认。
- 网页关闭提示页已有 fake 合同测试覆盖，但尚未在部署后的真实浏览器入口验收；外层反向代理如果启用了错误页拦截，仍需确认不会替换 Gateway 返回的 HTML。
