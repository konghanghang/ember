# Ember v2.1.0

## 本次更新

本版本扩展 Playback Gateway 的 115 播放能力，新增用户自有账号、套餐账号来源、Redis 播放租约与转存配额，以及可选的 STRM 本地媒体回退；同时收口用户账号中心、管理员中心导航和 Web/Bot API 响应合同。正常 Emby 代理播放仍是基线，115 与本地文件只作为可选加速路径。

## 重点功能

- 普通用户可以在账号中心按“绑定 Cookie → 验证 Cookie → 配置已有目录与最大播放路数 → 启用”维护本人唯一的 115 playback 账号。Cookie 保持只写，后端从唯一合法 `UID` 自动识别已知客户端类型，未知编码保存为 `unknown`。
- 套餐组新增 `personal|system` 账号来源，以及每用户滚动小时和 `CRON_TIMEZONE` 自然日转存额度。默认值为 `personal / 5 / 10`；`system` 显式使用管理员共享 playback 账号。
- Gateway 使用 Redis 原子维护 `reservation → active ↔ paused → stopped/expired` 播放租约、账号并发准入和转存额度。HEAD 无既有租约时不创建占用；Redis 不可用时停止签发新的 115 `302`，合法请求继续回退本地文件或 Emby。
- 管理员共享 playback 账号新增已有目录路径、最大播放路数和 Redis 当前用量；目录解析、账号版本和启用完整性由后端原子校验。
- 新增可选的 STRM 本地媒体回退。115 直连失败后，Gateway 可按可信 `MediaSource.Path` 的精确相对路径读取只读挂载文件；本地未命中或请求不支持时继续透明回退 Emby/CloudDrive2。

## 问题修复

- 115 source/playback 账号会根据真实 Provider 结果回写成功、凭证失效、协议错误和临时冷却状态；冷却到期只允许一个半开探测，旧请求不能覆盖 Cookie 替换或管理员新状态。
- 停用的个人 115 账号不再进入 Redis 准入，避免无效账号占用播放租约。
- 修复 Web 注册切换账号时的中间登出状态，以及设备页多个数据区不能统一刷新的问题。
- 统一媒体统计 camelCase 字段和 TMDB 搜索 `{data,total}` 响应合同，修复 Web 与 Telegram Bot `/count`、`/search` 对旧字段的依赖。

## 体验优化

- 用户 115 配置并入账号中心，保留旧 `/console/p115` 兼容跳转；页面按账号状态渐进展示验证、目录、并发和启用步骤。
- 管理控制台收口为用户中心、计费中心和播放中心，统一页头、分段导航和嵌入页面职责，减少重复入口。
- GitHub Actions 更新到 Node 24 运行时兼容版本；Bot 的 Python 版本约束下沉到 `services/bot/.python-version` 并固定为 Python 3.11。

## 升级说明

- 升级前应先备份 PostgreSQL。本版本包含 `20260903_01_p115_personal_routing_and_quotas.sql`，API 镜像已携带 migration，启动期自动执行并由 `VerifySchema` 校验，不需要手工运行 SQL；最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- migration 会把历史套餐组的 115 账号来源设为 `personal`。升级后，没有已启用个人账号的用户会回退正常 Emby 播放，不再隐式使用管理员共享 115；需要继续共享直连的套餐组必须由管理员显式改为 `system`。
- 旧管理员 playback 账号缺少新增的目录路径和最大播放路数，migration 会保留凭证和目标目录 ID，但将不完整的已启用账号停用。升级后需要在管理员 115 页面重新提交已有目录路径与正整数并发上限，再显式启用。
- `gateway` profile 现在同时启动内置 `redis:alpine`，开启 AOF 并使用 `redis_data` 持久卷。该默认镜像是浮动标签，不作为版本兼容承诺；API 与 Gateway 共用 `REDIS_URL`，外部 Redis 可以覆盖该地址，但连接串可能包含凭证，不得写入仓库或日志。
- Redis 当前只支持单 Gateway，不支持多副本、Redis Cluster 或跨主机时钟协调。Redis 数据丢失后租约和额度从空 Key 重新计数，不从 PostgreSQL 或 transfer 历史恢复。
- `PLAYBACK_LOCAL_MEDIA_ROOT` 默认留空，本地媒体回退保持关闭。启用时必须填写 Gateway 容器内规范化绝对路径，并通过部署环境自己的 Compose override 把宿主机媒体目录只读挂载到该路径；115 正式目录与本地根目录下的相对路径、大小写和文件名必须完全一致。
- 新增部署变量为 `REDIS_URL`、`REDIS_IMAGE` 和 `PLAYBACK_LOCAL_MEDIA_ROOT`。已有环境必须保持原 `JWT_SECRET`、`CONFIG_ENCRYPTION_KEY` 与 `INTERNAL_API_SECRET`，升级时不得重新生成。
- API 与 Gateway 必须继续使用完全相同的 `EMBER_API_IMAGE` Tag；Compose 默认 API、Web、Bot 镜像已同步更新为 `v2.1.0`。
- 部署前应使用目标环境实际 `.env`、Compose override 和只读 mount 执行 `docker compose config --quiet`。部署后首先检查 `ember-api` 的 `[Migrate]` 日志，确认进入预期的 forward-only 分支且 `VerifySchema` 成功。

## 已知限制与验证边界

- 自动化测试、关键并发 race、专用 PostgreSQL migration 集成测试和占位配置 Compose 解析已经通过；测试没有请求真实 Emby、115、Redis 或 Telegram。
- 既有管理员共享 115 的 Infuse `302`、字幕和 Playing/Progress/Stopped 事件已有受控实机证据；本版本新增的个人 Cookie、真实 `personal|system` 路由、Redis 租约/配额、Redis 故障回退和 Gateway 本地文件读取尚未执行真实客户端验收。
- 个人 Cookie 普通 Provider 请求使用固定 `Mozilla/5.0`，该默认值尚未经过目标个人 Cookie 的真实 115 验证；115 CDN 完整响应头、Range、全文件字节、UA/IP 绑定和长期风控仍未形成完整合同。
- 115 `302` 与 Gateway 本地文件都会绕过 Emby 视频上游；当前没有证据证明 Emby `SimultaneousStreamLimit` 能限制这些分流播放，本版本不把该行为声明为并发保证。
- 已知 [Issue #8](https://github.com/konghanghang/ember/issues/8)：Gateway 会把 `/Users/{UserId}/Items/Latest` 误判为单条详情并输出无效诊断日志；原始 Emby 响应仍透明返回，目前未观察到用户可见请求失败。
