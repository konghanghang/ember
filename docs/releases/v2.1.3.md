# Ember v2.1.3

## 本次更新

本版本修复播放排行榜的批次保存、即时查询、统计范围与日期边界，补齐 Telegram 通知结果反馈，并改善 Gateway 对客户端应用元数据的兼容性。

## 问题修复

- 排行榜以完整批次保存电影、剧集明细和总时长，修复一期只能保存部分明细的问题。空榜也保留批次，同一周期重复生成不追加明细、不重复通知；批次或明细写入失败时整体回滚。
- 修复日榜、周榜在周期尚未结束时生成后无法立即查询的问题；页面和 Bot 按全局业务时区展示统计日期及实际生成时间，不再把计划时间或周期结束时间当作生成时间。
- 电影按稳定条目 ID 聚合，剧集按 Series 归并；总时长在媒体库筛选后、上榜门槛与 Top N 截取前计算，扣除暂停时间，避免只统计榜单头部。条目信息明确缺失时跳过并记录，外部请求失败仍终止生成。
- 已选媒体库全部失效时保留空范围，不再自动扩大为全库统计；管理员可重新选择或显式恢复全库。手动生成的开始、结束日期均包含在统计范围内，修复结束日最后一秒的小数秒数据遗漏。
- Gateway 接受非身份应用元数据的无引号参数形式，修复此类合法客户端请求被拒绝的问题。Token 仍要求带引号，保留重复字段、身份冲突及非法字符检查，不扩大鉴权权限。

## 体验优化

- 媒体库归属回查只继续查询尚未匹配的条目，减少多媒体库下的重复请求，保持现有筛选和统计口径。
- 排行榜通知区分已发送、未配置目的地而跳过、结果未确认，并通过批次标识关联日志。通知失败不回滚已保存榜单，也不自动重试或补发；榜单仍可在页面查询。
- Gateway 增加请求头解析失败原因、字段标签和字节位置诊断，不记录 Token 或原始请求头。

## 升级说明

- 相比 `v2.1.2`，新增 `20260929_01_playback_ranking_batches.sql`。API 启动期自动创建 `playback_ranking_batches`、回填历史批次，并调整明细唯一索引和外键；不需要手工执行 SQL，也不依赖 `AUTO_MIGRATE`。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- 升级前备份 PostgreSQL，并保留现用镜像版本、部署配置及恢复步骤。迁移保留现存历史明细，但无法恢复过去未成功保存的明细或完整总时长，历史总时长保留未知值；不重新查询外部系统、不重算或补推历史榜单。
- 此迁移改变旧版依赖的索引和约束，未验证仅切回旧镜像的兼容性。需要回退时应停止写入，按已核对的恢复方案恢复升级前数据库与对应旧版应用；恢复备份会丢失备份之后的写入，不能把镜像降级当作数据库回退。
- 本版本没有新增配置项、环境变量或 Redis key。排行榜开关、调度和 `CRON_TIMEZONE` 以设置中心数据库值为准，同名环境变量不作为运行期回退；旧环境值需显式导入。排行榜默认关闭，启用时需同时开启 `CRON_ENABLED` 与 `RANKING_CRON_ENABLED`；默认日榜每天 20:00、周榜周日 20:30，读取当前日 / 周执行时已有数据。调度配置修改后需重启 API；Emby 运行时区必须与 `CRON_TIMEZONE` 一致。
- API、Web、Bot 默认镜像更新为 `v2.1.3`。API 与 Gateway 必须使用相同的 `EMBER_API_IMAGE`，已启用的 Bot 应同步升级以提供明确通知反馈；旧 Bot 响应只记为未确认，不据此重复发送。已在 `.env` 或 Compose override 固定镜像的部署应同步更新覆盖值，保持既有密钥不变。
- 从 `v2.1.1` 或更早版本升级时，还需阅读 [v2.1.2 升级说明](./v2.1.2.md#升级说明)，尤其是新增 115 转存所需的明确起播许可及 STRM-only 回退边界。
- 部署前使用实际 `.env`、Compose override 和已启用的 profile 执行 `docker compose config --quiet`；部署后检查 `[Migrate]` 与 `VerifySchema` 结果，并验证登录、排行榜查询与生成、通知反馈及目标播放器播放。

## 已知限制与验证边界

- 本轮基于 `0e9e7b48` 验证：Go 在独立干净副本运行 `go test ./...`、`go vet ./...`、`go build ./...` 均通过，测试进程已配置专用 PostgreSQL 集成库；Web 266 项测试通过、3 项集成测试跳过，类型检查与生产构建通过；Bot 77 项测试与入口语法检查通过。外部依赖使用 fake / mock，不代表真实 Emby、Telegram、115、Redis 或播放器验收。
- 本轮另行执行排行榜 PostgreSQL 专项并核对逐项结果，覆盖旧库升级、新装与 schema 校验、历史回填、重复迁移、四路并发、明细冲突回滚后重试、空榜与未来批次排除、历史完整 / 部分周期查询，全部通过；测试使用隔离 schema 并自动清理，未启动数据库或项目服务。
- 发布材料预检和包含 Gateway / Bot profile 的占位配置 Compose 解析通过；实际生产 `.env` 与 override 尚未校验。代码基线的 GitHub Test 通过（Bot job 按路径跳过），API / Web / Bot 预览镜像构建通过；这些结果不代表正式 Tag 镜像已经构建或生产已经部署。
- `npm ci` 全依赖审计报告 15 项告警（1 low、5 moderate、9 high）；`npm audit --omit=dev` 报告生产依赖 0 项告警。本次不修改依赖版本，开发 / 构建依赖告警保留为独立事项。
- 实际安装的 Playback Reporting 版本与媒体库组合筛选行为仍未实机核实，生产查询容量与本次客户端兼容修复仍需目标环境验收。已有历史快照不追溯重算；继续只支持单 Gateway，不支持 Redis Cluster。
