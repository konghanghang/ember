# Ember v2.4.0

## 本次更新

本版本完善 Gateway 的图片、认证、视频首请求和续播兼容，新增管理员可选的首次转存兼容模式，并改进 115 请求限流、失败隔离与播放诊断。同时修复观看保号规则修改时重置考核起点的问题，统一控制台与后台页面布局。

首次转存默认仍使用严格模式。客户端协议适配已有自动化覆盖，Yamby、SenPlayer 等客户端的本轮实机结果仍待验证，具体边界见下文。

## 重点功能

- **可选的首次转存兼容模式**：设置中心新增 `P115_TRANSFER_TRIGGER_MODE`。默认 `strict` 要求明确起播许可；管理员选择 `compatible` 后，符合原文件、身份、媒体证明、账号、租约及配额条件的视频 GET 可以在目标文件缺失时触发转存。HEAD 始终不新增转存。
- **源文件 preID 复用**：为同一源文件复用成功的 preID 哈希与并发读取结果，减少多个播放目标的重复源片段读取；各用户的目标查重、任务、配额与权限检查仍独立执行。实际命中率及起播时延收益尚未实测。
- **Gateway 排障工具**：新增可独立使用的抓包、脱敏日志采集与离线摘要工具，支持 SSH 跳转；补充认证、缓存命中原因和播放准备阶段诊断，便于区分网关处理与客户端、CDN 阶段。使用方式见[抓包与播放排查手册](../runbooks/gateway-packet-capture.md)。

## 问题修复

- 图片访问与 Emby 网页访问开关分离，关闭网页入口不再同时拦截符合合同的媒体图片请求；携带 Token 的请求继续执行身份与撤销检查。
- 兼容已支持认证头中 `Emby` / `MediaBrowser` scheme 的大小写差异，以及播放会话事件路径的大小写差异；Token 内容、冲突检测和权限边界保持原有语义。
- 扩展符合合同的视频首请求补查，并增加 SenPlayer `original.mkv` 原文件请求的受限识别；固定会话的媒体证明过期后，可在会话仍有效且身份完整匹配时重新核验。
- 修复停止事件处理受客户端断连影响、旧播放证明覆盖新状态等问题；请求取消或超时不再写入设置共享负缓存，避免影响后续正常请求。
- 细化文件不可用、直链过期、秒传拒绝与账号级故障分类，避免文件或请求失败错误改变 115 账号健康状态；缓存命中不冒充真实账号恢复成功。
- 改进 115 Cookie/Web 请求的进程内按账号 FIFO 限流，区分本地排队超时与上游 HTTP `429`，取消等待及时退出；源取链与源片段读取分别使用阶段预算，减少阶段间相互挤占。
- 修复观看保号开关、周期或分钟门槛变更时重开考核周期的问题，统一使用权益实际生效／接替时间作为起点；历史起点缺失时跳过考核并记录原因。

## 体验优化

- 统一控制台与管理员页面的标题、筛选、表格、分页和弹窗布局，完善窄屏展示。
- 整理账号中心分段与个人 115 账号区域，减少重复布局和无效留白；管理员侧栏不再展示普通用户的续费入口。
- 优化前端分包与资源加载，清理不再使用的页面状态。

## 升级说明

- **本版本包含 1 份数据库迁移**：`20261018_01_remove_watch_retention_reset.sql` 删除 `plan_groups.watch_retention_reset_at` 并替换保号规则约束，不改写权益起点、失效状态或历史审计。SQL 随 API 镜像分发，由 API/Gateway 启动期 Migrate 自动处理；支持窗口内通常无需手工执行 SQL，已应用的预览环境按迁移记账跳过。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点，无 baseline 压缩或迁移归档。
- **升级前备份数据库，并先停止旧 API 与 Gateway，再启动新版本。** 两个进程都会执行启动迁移，旧进程不能继续访问已删除字段。API、Gateway、Web、Bot 使用同一发布版本，API 与 Gateway 共用 `EMBER_API_IMAGE`；启动后确认 `[Migrate]` 完成、schema 校验通过且容器健康。迁移后不能仅切回旧镜像回滚，须配套恢复兼容 schema 或升级前备份，详见[观看保号起点规则升级](../runbooks/watch-retention.md#2026-10-18-起点规则升级)。
- **观看保号行为变化**：开启、重新开启或修改保号规则，均保留权益原有生效／接替起点。已满新规则周期的用户可在下一次正常调度参与考核，不再额外获得从配置修改日起算的完整周期；保存配置本身不执行考核。原本关闭的分组不会因升级自动开启；缺少可信起点的历史权益继续跳过，不以注册时间或迁移时间推算。业务日期仍使用 `CRON_TIMEZONE`。
- **兼容模式需要管理员主动开启**：`P115_TRANSFER_TRIGGER_MODE` 只在设置中心管理，不读取环境变量；缺失记录为 `strict`。SenPlayer 等客户端缺少明确起播许可时，严格模式仍只能复用已有目标，无目标则回退 Emby。`compatible` 作用于所有客户端，包含 Infuse 在内的视频预读也可能触发转存并消耗配额；关闭模式不能撤销已经开始的转存。正常配置读取下，修改最多经过一个五秒缓存窗口生效。
- **新增可选限流环境变量**：Compose 向 API 与 Gateway 同时传入 `P115_DATA_PLANE_RPS`、`P115_DATA_PLANE_BURST`、`P115_DATA_PLANE_MAX_WAIT`、`P115_RATE_LIMIT_COOLDOWN`、`P115_RISK_CONTROL_COOLDOWN`。默认分别为 `2`、`4`、`2s`、`15s`、`30s`，无新增必填变量；自定义 Compose 若要覆盖默认值，需要同步添加这些映射。风控冷却配置尚无已验证的 HTTP 触发源，裸 `403` 不按账号风控处理。
- Compose 默认镜像更新为 `v2.4.0`；使用 `.env` 或 override 固定镜像的部署需要同步调整覆盖值。Gateway 继续按单实例运行，Bot 更新模式及既有密钥配置保持不变。
- 从早于 `v2.3.0` 的版本跨越升级，仍须阅读 [v2.3.0](./v2.3.0.md#升级说明) 和 [v2.2.0](./v2.2.0.md#升级说明) 的升级要求，尤其是权益改版、旧兑换码与观看统计依赖。

## 已知限制与验证边界

- 发布材料基于 `deaa1bb1`；业务代码与 `e78d8f80` 一致。[Test 40188457875](https://github.com/konghanghang/ember/actions/runs/40188457875) 全部通过，包含 API、Web、Bot、Python 3.9/3.11 采集测试、Gateway 五包 race 与 Go→Python 日志契约。API CI 配置独立 PostgreSQL 集成测试；迁移用例覆盖新装、旧 schema 升级、重复执行及权益记录保留。本轮整理发布材料复用这些结果，未重新执行业务测试。
- 同一提交的 [API](https://github.com/konghanghang/ember/actions/runs/40188866570)、[Web](https://github.com/konghanghang/ember/actions/runs/40188866545)、[Bot](https://github.com/konghanghang/ember/actions/runs/40188866534) 预览镜像构建成功，预览部署已核对四容器 revision 与健康，稳定后观察 4 分钟无新增重启，Bot polling 租约持续有效。更新期间 Bot 曾出现租约占用提示并自动恢复；这些结果不代表正式版本镜像已经构建，也不替代业务验收。
- **客户端实机验收仍未完成**：本轮尚未逐项确认 Yamby 首页图片、SenPlayer 首次／复用转存、Infuse 回归、五分钟后拖动续播、暂停／停止、字幕与完整播放。自动化、Gateway `302`、CDN `206` 或容器健康不能代替这些结果；不宣称已全面兼容所有客户端或取得真实首帧性能改善。
- 个人 115 Cookie、账号路由、Redis／配额故障路径，以及真实观看保号考核与 Emby 权限同步仍有待验收项，继续按现行清单跟踪。Telegram 群签到与“观看或签到任一达标即可保号”尚未实现。
- 本次未升级依赖，也未重新执行依赖审计；[v2.3.0 记录的审计告警及验证边界](./v2.3.0.md#已知限制与验证边界)不视为已解决。正式发布仍需确认版本 Tag 的三个镜像构建和 Draft Release 工作流成功。
