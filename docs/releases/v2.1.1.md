# Ember v2.1.1

## 本次更新

本版本修复支付续期、订阅审批、排行榜、账号同步与 Telegram 通知中的一致性问题，并优化 115 路径解析、数据库写入和同设备重播。Gateway 继续以正常 Emby 代理播放为基线，115 作为可选加速路径。

## 问题修复

- 支付重试使用订单保存的金额、币种和天数，避免套餐改价后实际收费与履约快照不一致；已确认付款的晚到成功回调不再仅因本地订单失败、过期或事件时间较早而被忽略，已完成订单仍保持幂等。
- 支付、兑换和管理员续期按用户串行更新到期日，避免并发操作丢失续期天数；Emby Policy 同步按用户串行读取最新权益，取消任务时不再提前占用尚未开始的任务。
- 本人取消待审核订阅改为原子状态校验；缺集工单的旧搜索、下发和扫描结果不再覆盖已结束状态，页面遇到状态冲突后刷新权威结果。
- 历史排行榜包含完整周期快照；剧集榜先完整聚合候选与单集时长，再执行白名单过滤和排名，修复漏榜与时长少算。
- Telegram 拒绝审批保留待输入上下文以支持失败重试，并使用服务端最终审批结果更新消息；通知与搜索结果按 Telegram 文本/图片说明限制安全处理 HTML。清空群配置后移除旧缓存目的地。
- 管理员账号重置密码仅更新 Ember 本地密码，不再依赖 Emby；资料加载遇到网络或服务端故障时保留登录凭据并提供重试入口，认证失效仍正常退出。
- Gateway 登录请求交由 Emby 判定，支持从 JSON/XML 成功响应建立本地映射，修复应用元数据校验阻断原生认证的问题；公开用户与头像入口不再依赖完整应用元数据。用户条目静态路由不再被误判为单条详情，收口 v2.1.0 的已知 Issue #8。
- 115 源路径解析失败不再错误污染账号健康状态；修复内容锁等待占用连接池、播放租约丢失后仍签发直链，以及健康回写干扰配置更新等竞争边界。

## 体验优化

- 优化 115 源路径定位，合并相同父目录的并发读取，并在现有决策日志中补充阶段耗时，便于定位慢请求。
- 对播放成功记录按一分钟采样，减少重复数据库写入；独立配置版本避免健康状态更新使播放路由和目录保存失效。
- 同一设备、同一登录映射内的短期重播可复用最终直链，缓存最长 30 秒且受链接到期时间限制；每次请求仍执行身份、账号、套餐与播放租约校验，不跨设备共享。

## 升级说明

- 升级前备份 PostgreSQL。本版本包含 `20260912_01_p115_account_config_version.sql`，为 `p115_accounts` 增加 `config_version`，已有行默认初始化为 `1`；重复执行保留已有代次，无需业务回填。
- API 镜像携带 migration，由启动期自动执行并通过 `VerifySchema` 校验，不需要手工执行 SQL。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点；从早于 v2.1.0 的版本升级时，还需阅读 [v2.1.0 升级说明](./v2.1.0.md#升级说明)，特别是套餐默认 personal、共享账号配置与 Redis 部署要求。
- 本版本没有新增部署环境变量，也不改变默认服务拓扑。API 与 Gateway 必须使用相同的 `EMBER_API_IMAGE` Tag；API、Web、Bot 默认镜像均更新为 `v2.1.1`。已在 `.env` 或 Compose override 固定镜像的部署应同步更新相应覆盖值。
- Telegram 拒绝审批使用新增的 Internal API 端点，启用 Bot 的部署应同步升级 API 与 Bot；滚动升级时先升级 API，再升级 Bot。
- 保持既有 `JWT_SECRET`、`CONFIG_ENCRYPTION_KEY` 与 `INTERNAL_API_SECRET`，不要在升级时重新生成。部署前使用目标环境实际 `.env` 和 override 执行 `docker compose config --quiet`；部署后检查 API 的 `[Migrate]` 日志和 `VerifySchema` 结果。

## 已知限制与验证边界

- 发布准备已通过 API 全量非数据库测试、`go vet` 与编译；Web 262 项测试通过、3 项集成用例跳过，类型检查与生产构建通过；Bot 70 项测试及 7 个子测试通过，入口语法检查通过。包含 Gateway/Bot profile 的占位配置 Compose 解析通过，仍需部署者校验实际环境配置。
- DirectPlay 专项已在专用 PostgreSQL 执行，13 个顶层测试及 2 个子测试全部通过，覆盖配置版本 migration、目录保存竞争、成功记录采样和小连接池锁等待取消；115 Provider 使用 fake。其他模块的自动化证据不能扩展为真实第三方链路验收。
- Gateway 认证修复后的 Yamby 登录、媒体库和实际播放，以及 Infuse/SenPlayer 回归仍待部署者验证；XML 认证响应目前只有自动化合同证据。
- 个人 115 Cookie、真实 personal/system 路由、Redis 租约/配额与故障回退、短期直链缓存的实际播放器收益仍未完成受控真实验收。既有 Infuse 共享账号播放证据不代表上述新增或变更链路已通过。
- 115 CDN 完整响应头、Range、全文件字节及长期风控边界仍未形成完整实机合同；Emby 的并发限制能否覆盖 115 `302` 分流仍未证实。继续只支持单 Gateway，不支持 Redis Cluster。
