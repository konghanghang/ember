# Ember v2.0.2

## 本次更新

本版本继续收口 `v2.0` Playback Gateway 的客户端兼容、Emby 回退、115 路径解析和运行日志，重点解决 Infuse 登录、扫库和播放请求中的真实兼容问题，并补齐跨 API、Gateway、Bot 的统一日志级别。

目标环境已经确认 Infuse `8.5.2` 可通过 Gateway 完成根路径发现、登录、普通资源请求、按需 PlaybackInfo、`Size=0` 媒体的 115 source 映射与 Gateway `302`。这些证据只证明 Gateway 已返回 115 重定向，不证明客户端已完成 115 CDN 媒体字节、Range、字幕或完整播放会话。

## 问题修复

- 扩展 Gateway 的 Emby 4.9 客户端兼容边界：支持 root/`/emby` API family 的大小写兼容、Infuse 使用的 `MediaBrowser` 应用头与内嵌 Token，以及固定直接 Header/query Token aliases；重复、冲突和非法载体继续失败关闭。
- 按真实 Infuse 行为允许精确 `GET /System/Info/Public` 无本地应用头访问；认证成功响应继续逐字节返回，并对有界旁路副本兼容 `identity/gzip/deflate`，修复 deflate 响应无法建立 Token 映射的问题。
- plain 视频请求缺少 PlaySessionId/Container 时按需补取权威 PlaybackInfo，优先采用经过严格校验和 Token 清理的 DirectStreamUrl，否则补齐扩展名形成独立 Emby fallback；请求 method、Range、应用头和非身份参数保持不变。
- Token Store 正确区分请求取消、deadline 和真实存储故障：前两者分别返回 `499/504`，不再误报 `token_store_unavailable`；仅对 driver 明确保证尚未发送的幂等读错误重试一次。
- 恢复历史 `CONFIG_ENCRYPTION_KEY` 兼容：已有非空、无首尾空白和换行的密钥不再被新增长度建议阻断。已有环境必须保持原值，新部署仍建议使用随机至少 32 字节密钥。
- 115 源文件解析不再依赖 Emby Size。`Size=0`、缺失或异常只作为观察值；DirectPlay 按 sourceRootId、完整相对目录链和最终文件名唯一解析，并使用 115 Provider 返回的正数 Size/SHA1 驱动查重、秒传和任务状态。

## 运维优化

- API、Gateway、Bot 共用可选 `LOG_LEVEL=info|debug`，默认 `info`。Debug 增加安全请求摘要、普通 access、参数化 SQL 和缓存诊断；第三方 HTTP logger、Token、Cookie、Authorization 和 query value 不随之放宽。
- Go 统一入口会在日志初始化前按 `EMBER_DOTENV`、当前目录 `.env`、`services/api/.env` 的顺序选择 dotenv，已有系统环境变量优先且不被覆盖。
- Gateway 增加脱敏启动失败原因码、统一 `request_completed` 摘要和中文播放结论。115 直链成功会明确记录 `statusCode=302` 与首次/复用状态；失败会记录固定 Provider 步骤或 `source/playback` 账号角色，并说明 Emby fallback 最终成功或失败。
- 按运维排障授权，Gateway 持久日志会记录选中的完整 Emby 媒体 Path、source 前缀和映射后相对路径；仍禁止记录 115 下载 URL、完整 SHA1、Token、Cookie、响应体或 Provider 原始错误。部署者应为 Gateway 日志设置合适的文件权限和保留周期。
- Bot 关闭 Uvicorn 原生 access log，使用不含 query value 和真实路径参数的路由模板摘要；`httpx/httpcore/telegram` 始终保持 `WARNING`，避免 Debug 暴露 Bot API 请求上下文。
- 生产镜像继续只包含一个 `ember` 二进制，通过 `ember api` 与 `ember gateway` 选择进程角色；源码中的旧 `cmd/server`、`cmd/playback-gateway` 薄入口已经删除。

## 升级说明

- 本版本不包含新的数据库 migration，不需要手工执行 SQL；最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- `LOG_LEVEL` 是可选配置，未配置时继续使用 `info`，已有部署无需修改 `.env`。需要排障时可临时设置 `LOG_LEVEL=debug` 并重启对应服务。
- `CONFIG_ENCRYPTION_KEY` 必须保持现有值，禁止仅为满足新部署建议而补长或替换，否则已有敏感配置、115 Cookie 和 Emby Token 映射将无法继续使用。
- API 与 Gateway 必须使用完全相同的 `EMBER_API_IMAGE` Tag；Compose 默认 API、Web、Bot 镜像已同步更新为 `v2.0.2`。
- 如果维护脚本曾直接执行 `go run ./cmd/server` 或 `go run ./cmd/playback-gateway`，改用 `go run ./cmd/ember api` 或 `go run ./cmd/ember gateway`。Docker Compose 用户无需额外处理。
- Gateway 反向代理 access log 禁止记录完整 query。Emby 客户端可能通过 `api_key`、`AccessToken`、`X-Emby-Token` 等 query carrier 携带凭证，应只记录 `$uri`，不能记录 `$request_uri`、`$args` 或完整请求行。
- 已确认 Gateway 可为目标 `Size=0` 媒体完成 source 映射、转存和多次 `302`；但后续连续请求曾出现 `provider_unavailable`，对应 Emby 扩展名 fallback 返回 `404`。115 CDN 字节、HEAD/Range、字幕、Progress/Stopped 以及其他播放器仍未完成真实验收。
- 原始 Emby 公网入口未隔离时，客户端仍可绕过 Gateway 的本地 Token 撤销和用户状态门控；生产接入必须只公开 Gateway HTTPS 入口。
