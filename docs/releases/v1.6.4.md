# Ember v1.6.4

## 本次更新

本版本修复播放排行榜在选择部分 Emby 媒体库后出现空榜的问题，并统一排行榜、播放历史和用户播放画像的时间边界语义。

## 问题修复

- 修复媒体库 allowlist 使用错误查询上下文判断条目归属，导致选择部分媒体库后候选条目被全部过滤的问题。
- 修复媒体库归属缓存未完整区分管理员、媒体类型和 allowlist 范围，避免不同查询条件之间复用错误结果。
- 修复 Playback Reporting SQL 错误仍以 HTTP `200` 返回时被误判为空榜的问题；现在会保留明确错误而不是静默生成空结果。
- 修复排行榜相邻周期在结束时刻重复统计的问题，统计范围统一为半开区间 `[start, end)`。
- 修复排行榜、播放历史和用户播放画像对 Playback Reporting 本地时间进行无条件 UTC 转换的问题，统一使用全局 `CRON_TIMEZONE`。
- 修复无法找到明确 Emby 管理员时静默回退普通用户的问题，避免媒体库列表和可见条目范围被错误缩小。

## 兼容性与维护

- 增加 Emby Server `4.9.3.0` 与 Playback Reporting 固定源码版本的 API 合同，明确接口、字段、时间和错误语义。
- 媒体库视图和成员查询统一使用同一个 Emby 管理员上下文，并校验返回条目必须属于请求候选。
- Playback Reporting schema 改为使用无数据的 `LIMIT 0` 查询校验，不读取真实播放记录。

## 升级说明

- 本版本不包含数据库 schema 变更，无需手工执行 SQL。
- 无新增配置项；现有 `CRON_TIMEZONE` 作为 Ember 全局业务时区，同时用于调度、排行榜、播放历史和用户播放画像。
- Playback Reporting 的 `DateCreated` 使用 Emby Server 本地时间。部署时必须确保 Emby Server 运行时区与 `CRON_TIMEZONE` 一致，否则统计周期仍会产生偏移。
- 按现有部署流程执行 `docker compose pull && docker compose up -d` 即可。
- Docker Compose 默认镜像 tag 已同步更新为 `v1.6.4`。
