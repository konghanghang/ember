# Ember v2.0.0

## 本次更新

本版本新增可选的 115 Cookie 直连播放 Gateway、管理员 115 账号控制面和完整的 Emby Token 门控，同时完成前端类型、状态层与控制台布局收口。Gateway 默认不启动；不启用 `gateway` profile 时，现有 Ember API、Web、Bot 和原始 Emby 访问方式保持原部署边界。

真实 Infuse、目标 Emby 与 115 CDN 的端到端播放仍未完成生产验收。本版本提供的是经过 fake、固定合同和 PostgreSQL 集成测试保护的实现，建议发布后先使用独立 Gateway 域名和单个测试账号验证，再决定是否扩大使用范围。

## 重点功能

- 新增管理员 115 source/playback 账号控制面，支持 Cookie 加密保存、替换、显式验证、启停、source Emby 路径映射和 playback 目标目录配置；Cookie 不回显、不写日志。
- 新增原生 Go Cookie Provider，覆盖源文件定位、SHA1 查重、Range Hash、秒传初始化、目标文件复核和 playback 账号下载 URL；运行时不依赖 Python 或 `p115client`。
- 新增保留式 DirectPlay 编排，以 PostgreSQL advisory lock 和 transfer task 保证同内容并发只执行一次秒传；115 任一步失败时，合法用户透明回退原始 Emby 播放。
- 新增独立 `ember gateway` 进程，与 API 复用同一个 `ember-api` 镜像和单二进制；API 使用 `8080`，Gateway 固定监听 `8081`，Compose 通过可选 `gateway` profile 启用。
- 新增 Emby 登录透明代理、AccessToken 单向 HMAC 映射、实时用户状态检查和本地撤销；用户停用、Emby 访问禁用、解绑、删除和设备注销会先撤销 Gateway 登录映射。
- Gateway 代理 PlaybackInfo、播放开始、进度和停止事件，并以短期进程内证明保护 115 直连；支持范围为 `>= 4.9.0.0 && < 4.10.0.0`。
- 新增 115 账号管理页面；source/playback 账号、验证状态、目录配置和敏感凭证操作统一进入管理员控制台。

## 问题修复

- 修复 115 秒传响应解析与 playback 目录已有文件复用边界，避免把非成功结果或目录外文件误判为可播放目标。
- 修复媒体缺集扫描失败后按钮可能持续处于运行状态，以及视图切换时旧请求覆盖新结果的问题。
- 修复前端登录态跨标签页同步、401 竞态、幽灵登录残留和重复错误提示等状态层问题。
- 恢复支付记录筛选入口，移除支付、兑换和续期中心的重复标题与重复说明。
- 升级 Axios、Element Plus、Vue 和 PostCSS 的生产依赖安全基线，并同步修复 follow-redirects、form-data、Lodash 和 Nanoid 传递依赖；`npm audit --omit=dev` 已无已知漏洞。

## 体验与工程质量

- Web 生产构建接入 `vue-tsc --noEmit`，收口 API 请求层真实返回类型，并补充 auth、request、store、路由、共享工具和关键页面测试。
- 控制台页面统一复用 Ember 页头、筛选、分段、统计、日期和空状态组件，收敛按钮、弹窗、徽章、移动端导航和无障碍行为。
- 抽取日期、剪贴板、错误识别、格式化和 Policy 状态工具，删除无引用资源、死页面与无效依赖。
- 新增版本化 Emby 4.9 播放代理合同、115 Cookie/OpenAPI 合同、完整端到端流程图和部署/排障 runbook。

## 升级说明

- 当前最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点；旧于该截点且未执行过已归档增量的数据库，不能直接跳升。
- 本版本包含 4 份顶层数据库 migration：新建 `p115_accounts`、`playback_transfer_tasks`、`emby_access_tokens`，并为 source 账号增加 Emby 路径前缀和 115 源目录字段。
- migration 随 `ember-api` 镜像分发，由 API 启动期 `Migrate → VerifySchema` 自动执行；无需手工运行 SQL。升级前仍应完成数据库备份，并在启动后核对 `[Migrate]` 日志。
- 默认部署不启动 Gateway。先执行普通 `docker compose pull && docker compose up -d` 验证 v2 API/Web/Bot；确认正常后，再使用 `docker compose --profile gateway up -d ember-gateway` 启用 Gateway。
- API 与 Gateway 必须使用完全相同的 `EMBER_API_IMAGE` Tag。Compose 默认镜像 Tag 已同步更新为 `v2.0.0`。
- Gateway 固定监听容器内 `8081`；`PLAYBACK_GATEWAY_PORT` 只控制宿主机回环映射端口，默认同为 `8081`。旧的 `PLAYBACK_GATEWAY_LISTEN_ADDR` 已删除。
- `EMBY_URL` 和 `EMBY_API_KEY` 继续由设置中心数据库托管，必须指向 Gateway 可访问的原始 Emby；用于测试的 Gateway 新域名可以单独配置在反向代理和 Infuse 中，不要求立即切换现有用户域名。
- 首次通过 Gateway 使用的客户端需要重新登录，以建立 Token 摘要映射；历史 Emby Token 不会回填。原始 Emby 域名不切换时，现有客户端不会自动进入 Gateway。
- 115 文件在第一阶段作为 playback 账号持久缓存保留，不会因 Stopped 或会话过期自动删除；账号运行期冷却回写、持久播放会话、套餐权限、Gateway 并发和容量治理仍未实现。
- 真实 Infuse 请求形态、302/HEAD/Range 行为、115 长期风控和目标部署网络仍为“未证实”，不得把本次离线与 fake 验证表述为真实播放验收完成。
