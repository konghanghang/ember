# Ember v2.0.1

## 本次更新

本版本是 `v2.0.0` 的 Gateway 兼容性修复版本，解决 Infuse 首次连接使用根 API path 时被错误要求提供用户 AccessToken 的问题，并隔离 API 与 Gateway 的持久日志文件名。

Gateway 根路径、bootstrap 和登录修复已通过固定 Emby 4.9 合同、fake upstream、竞态测试和 API 全量测试；目标生产 Infuse 的应用授权头与完整登录仍需升级后复验，不能把本次自动化结果表述为真实播放验收完成。

## 问题修复

- Gateway 按支持范围内稳定 Emby 4.9 OpenAPI 顶层 API family 的并集，将 `/System/...`、`/Users/...`、`/Items/...`、`/Videos/...` 和 `/Sessions/...` 等客户端根路径规范化为单一上游 `/emby/...`；已经带 `/emby` 的请求保持兼容。
- 将精确 `GET /System/Info/Public` 纳入应用授权头保护的登录前 bootstrap，修复旧版本在 Infuse 首次连接时返回 `401 code=token_header_invalid`、无法进入用户名密码登录的问题。
- 根路径 AuthenticateByName、PlaybackInfo、视频和 Playing/Progress/Stopped 请求复用现有 Token 映射、短期证明、115 直连、Emby fallback 与默认透明代理处理器。
- 精确重复 `/emby/emby/...` 的请求返回空体 `400`，避免客户端路径前缀被重复拼接；根 `/web/...` 与未知 Surface 暂不参与 API 规范化。

## 运维优化

- API 与 Gateway 继续同时写 stdout 和按日文件，但持久文件名改为独立的 `api-YYYY-MM-DD.log` 与 `gateway-YYYY-MM-DD.log`；Compose 仍分别使用 `api_logs` 和 `gateway_logs` 日志卷。
- 登录前应用头无效时，Gateway 使用不含 Header 值的 `application_header_invalid route=public_bootstrap pathMode=root` 日志，便于区分路径兼容问题和真实客户端 Header 合同问题。

## 升级说明

- 本版本不包含新的数据库 migration，不需要手工执行 SQL；最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- 本版本没有新增或修改配置项、环境变量、端口和 Compose profile。API 与 Gateway 仍必须使用完全相同的 `EMBER_API_IMAGE` Tag，Compose 默认镜像 Tag 已同步更新为 `v2.0.1`。
- 从旧版本升级后，历史 `app-YYYY-MM-DD.log` 文件不会被删除；新进程分别写入 `api-YYYY-MM-DD.log` 和 `gateway-YYYY-MM-DD.log`。
- 使用 Gateway 的 Infuse 需要重新执行首次连接和用户名密码登录验证。预期 `GET /System/Info/Public` 不再进入 `token_header_invalid`；如果出现 `application_header_invalid`，表示真实 Infuse 应用授权头仍与当前固定合同不一致，应保留脱敏日志继续排查。
- 真实 Infuse 登录、PlaybackInfo、普通 Emby 视频 fallback、115 `302`、HEAD/Range 和进度事件仍未完成本版本生产验收。原始 Emby 公网入口未隔离时，也不能宣称 Gateway 本地撤销和访问门控不可绕过。
- Emby Web Surface 全局开关不包含在本版本中，根 `/web/...` 仍维持现有受保护透传边界。
