# Ember v2.2.0

## 本次更新

本版本重构套餐与分组授权：所有用户看到统一的套餐目录，每个套餐绑定一个权益分组，并明确设置限时或永久有效。用户可同时持有多个分组的独立权益，系统按最高等级有效分组提供资源，到期检查时自动回退到仍有效的低等级分组。

## 重点功能

- 套餐支持正整数天数或永久有效，购买后自动授予对应分组权益，无需用户手动切组。永久套餐是可选项，仅售限时套餐也可使用。
- 同组限时购买累计期限；跨组分别计时，不把原分组剩余时间转移到新分组，也不暂停原期限。永久基础权益可与限时增强权益并存。
- 分组继续承载 Emby 资源库与访问模板，新增权益等级和资源库逐级包含校验。媒体库、求片和 115 来源模式、并发及配额统一跟随当前生效组，不合并各组配置。
- 用户列表“编辑信息”支持更换分组，保留原期限和状态；目标组已有权益时拒绝覆盖。
- 后台新增用户权益管理，可按分组延长有效期、设置明确到期时间、设为永久或撤销权益；账号停用及人工禁用 Emby 访问保持独立限制。
- 支付订单保存购买时的权益快照，之后修改套餐分组或天数不改变已创建订单的交付内容。付款成功但不能自动发放的订单进入待人工处理，后台可记录线下退款结果或发放补偿权益；记录退款不会调用 Stripe 自动退款。

## 问题修复

- 修复求片用户查询漏读权益状态的问题，避免有效用户新建或重新提交求片时被误判为无权限。
- 改善支付迟到回调、重复通知和并发续期的处理，保留已付款事实，防止重复发放；已人工处理的订单不会因回调重放退回原状态。
- 修复后台调整权益后列表及已打开弹窗的状态刷新，避免继续显示旧分组；用户不再符合当前筛选时关闭旧权益弹窗。
- 套餐按当前分组名称展示，永久权益不显示为“0 天”；用户列表操作按钮统一单行排列并收紧多余留白。
- 统一分组权益等级按钮与编辑弹窗的 Ember 样式。

## 体验优化

- 续费中心展示统一价格与购买资格；已拥有永久权益、购买不会增加权益时明确提示。
- 重新整理套餐卡片层级：完整描述使用浅红背景和淡红描边，价格与期限组合展示，分组作为辅助信息；同排价格与购买区底部对齐，手机端减少嵌套留白。
- 港币套餐新增人民币参考价，暂按固定汇率 `1 HKD = 0.85 CNY` 换算，保留两位小数；人民币及其他币种不重复或猜测换算。参考价不参与订单计算，Stripe 仍按原币种和金额收款，实际扣款以支付渠道为准。
- 账号中心展示各组持有权益及当前生效组；Bot 账号信息区分无权益、限时与永久，支付通知按订单快照展示权益。
- 补充 Stripe CLI、Cloudflared 和 ngrok 的沙盒联调说明及回调重放验收方法，见 [支付测试指南](../runbooks/stripe-payment-testing.md)。

## 升级说明

- **本版本包含数据库迁移**：新增 `20261004_01_plan_group_entitlements.sql`，引入用户权益、审计、商品有效期及支付人工处理字段。SQL 随 API 镜像分发，由 API 启动期在事务内自动执行；从受支持的已发布版本升级无需手工执行 SQL。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点。
- **升级前备份数据库，并停止旧 API/Gateway 写入**。API、Gateway、Web 和 Bot 应同步升级；API 与 Gateway 必须使用同一个 `EMBER_API_IMAGE`。先确认 API 启动期 `[Migrate]` 完成，再恢复入口，避免旧实例继续按单一期限写入。迁移后不能仅切回旧镜像就视为完成回退。
- **迁移前已有兑换码全部失效**，包括注册和续期码；历史兑换记录、使用次数及已发放权益保留。升级后按需创建新码，迁移重复执行不会再次使新码失效。
- 现有普通用户按原分组和期限建立权益，原空期限按永久语义映射；不按历史支付重新累计授权，人工封禁状态不清除。旧套餐按原分组与正数天数转换为限时套餐；分组无法解析或套餐天数异常时迁移会拒绝执行，应先核对数据。
- **升级后须配置完整的分组权益等级**，并使高等级媒体库包含低等级范围。校验完成前暂停新套餐购买；已有目录、用户权益和已付款处理仍按各自规则运行。详细步骤见 [权益升级与验收](../runbooks/entitlements-upgrade.md)。
- 到期回退沿用 `CRON_ENABLED`、`CRON_SCHEDULE` 和全局业务时区 `CRON_TIMEZONE`。期限到达后允许等待下一轮定时检查，不新增实时到期任务；应确认部署环境已启用所需检查时间点。
- 外部商品 API 调用方需使用 `planGroup/validityType/days`；限时天数为正整数，永久明确使用 `permanent` 且存储天数为 0，不凭 0 推断永久。商品创建/编辑拒绝旧 `benefits` 输入，订单历史和人工补偿仍保留权益数组。用户编辑 API 仅提交 `planGroup` 时表示保留期限更换当前组；目标组已持有权益时返回冲突，不合并或覆盖。新增、延长和撤销权益仍使用权益管理接口。
- 升级前缺少权益快照的旧订单不会按现售套餐补造授权；已完成订单不重发，迟到付款且缺快照的订单进入待人工处理。曾使用未发布测试稿的环境需按升级手册先显式处理组合商品并核对迁移记账；不要清空迁移历史或直接覆盖 checksum。
- 默认镜像更新为 `v2.2.0`；使用 `.env` 或 Compose override 固定镜像的部署需同步更新覆盖值。没有新增必填环境变量，既有密钥保持不变。
