# Ember v2.1.2

## 本次更新

本版本收口 115 播放中的新增转存时机、播放信息响应乱序和管理员套餐路由问题，将媒体解析与直链缓存延长至十分钟，并补充播放链路诊断及前端兼容修复。

## 问题修复

- 新增转存必须取得客户端明确起播许可，避免仅浏览详情时的视频探测创建转存任务、消耗转存配额。已有目标文件与有效缓存继续复用；HEAD 不创建新转存。
- 修复较早的内部 PlaybackInfo 请求或客户端响应较晚完成时覆盖新起播许可的问题，防止响应乱序清除新许可或恢复已失效的播放证明。
- 管理员播放按所属有效套餐的 `personal/system` 策略选择个人或共享账号，不再因管理员角色被排除；个人账号管理入口的权限边界保持不变。
- 修复默认套餐分组删除提示渲染空节点的问题；系统设置和排行榜媒体库复选框改用显式选中值，消除组件弃用警告并保持原有选择与保存行为。

## 体验优化

- 同一设备、同一登录映射下的跨播放会话请求可复用媒体解析结果和最终直链，缓存最长十分钟，受原始直链到期时间限制且命中不续期，减少重复路径解析、目标查重和取链请求。每次请求仍校验身份、套餐、账号与播放租约；缓存不跨用户或设备共享，也不延长独立的 30 秒播放 reservation。
- 补充 PlaybackInfo 请求来源、起播字段状态、处理阶段耗时、缓存命中与租约变化的 Debug 诊断，便于区分客户端请求、Gateway 补查和缓存复用。缺少起播许可记录为“跳过新增转存”，不再误报为 115 Provider 故障；Emby 回退的真实状态仍单独保留。

## 升级说明

- 相比 `v2.1.1`，本版本没有新增数据库 schema 或 migration，不需要手工执行 SQL。最低直接升级支持版本仍为 `v1.6.0` / `2026-06-05` schema 截点；从更早的支持版本升级时，API 启动期仍自动执行尚未应用的 migration，并通过 `VerifySchema` 校验。跨版本升级请同时阅读 [v2.1.1 升级说明](./v2.1.1.md#升级说明)和 [v2.1.0 升级说明](./v2.1.0.md#升级说明)。
- 本版本没有新增环境变量、配置项或 Redis key，也不改变默认服务拓扑。API、Web、Bot 默认镜像更新为 `v2.1.2`；API 与 Gateway 必须使用相同的 `EMBER_API_IMAGE` Tag。已在 `.env` 或 Compose override 固定镜像的部署应同步更新覆盖值，保持既有密钥不变。
- 新增转存许可要求客户端 JSON POST PlaybackInfo 明确携带 `IsPlayback=true`，并由成功的 Emby 响应形成匹配的播放证明；许可固定有效 30 秒，成功停止事件撤销对应已记录许可。未提供该信号的客户端仍可复用已有目标，但目标不存在时回退 Emby，不能保证首次 115 加速。若 Emby 只有 STRM 中的本地路径、没有可读取的实际媒体，回退可能返回 404；升级前需核对实际播放器与媒体部署方式。
- 无额外手工数据库或配置迁移步骤。部署前使用目标环境实际 `.env` 和 override 执行 `docker compose config --quiet`，部署后检查 API 的 `[Migrate]` 日志与 `VerifySchema` 结果，并复验目标播放器的首次转存、停止后浏览和重播。

## 已知限制与验证边界

- 发布准备复用同一代码基线 `4de220f` 的本轮验证：Go 全量非集成测试、Gateway/DirectPlay/配额/账号/Token/Emby 六个关键包 race、`go vet` 与编译均通过；Web 265 项测试通过、3 项集成测试跳过，类型检查与生产构建通过；Bot 70 项测试及入口语法检查通过。该提交的 GitHub Test 工作流已通过，Bot job 因无改动跳过。新版材料预检与包含 Gateway/Bot profile 的占位配置 Compose 解析通过；实际部署配置仍需单独校验。自动化使用 fake 外部依赖，不代表真实 Emby、115、Redis 或播放器验收。
- 本轮没有重跑 DirectPlay 的真实 PostgreSQL 专项，普通 CI 不覆盖该专项；此前数据库验收记录不能扩展为本版本新增链路全部通过。详见 [测试指南](../runbooks/testing.md)。
- 2026-09-22 已记录用户反馈正常播放通过，但首次新转存、停止后再次浏览和重播尚未逐项完成操作与日志对照；不据此宣称所有播放器兼容。仅浏览详情时阻止新增转存后的 Emby 404 已在当前 STRM-only 部署记录，单集缺少 thumb 是否导致 Infuse 读取视频仍未证实。
- 十分钟缓存的实际播放器收益、115 CDN 完整响应头、Range、全文件字节及长期风控边界尚未形成完整实机证据；Emby 并发限制能否覆盖 115 `302` 分流仍未证实。继续只支持单 Gateway，不支持 Redis Cluster。
