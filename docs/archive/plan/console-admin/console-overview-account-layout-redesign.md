# 控制台概览与账号中心布局改造方案

> 状态：已归档
> 负责人：Ember
> 更新时间：2026-06-05

## 背景

当前控制台的“概览”和“账号中心”页面已经具备核心功能，但布局层级不够清晰：

- 概览页首屏同时呈现账号身份、会员状态、Telegram 状态、Emby 入口和片库统计，导致“服务可用性”这个核心问题不够突出。
- 账号中心页面内部重复承担页面标题职责，基础资料、安全设置、Emby 绑定、Telegram 绑定按源码顺序堆叠，核心操作不够聚焦。
- 两个页面存在多套卡片圆角、灰阶命名和强调色写法，和现行 Ember 前端设计规范的白底卡片、克制文案、品牌主操作基线不完全一致。

如果不调整，后续继续往页面里加账号资源、绑定状态、媒体摘要或安全提示，会让页面变成“功能堆叠”，而不是可扫描的控制台。

## 目标

本方案要实现：

1. 将概览页改成服务状态驾驶舱：首屏只呈现会员/服务状态、Emby 入口和片库数字，账号身份与绑定信息回收到 `TopBar` 和账号中心。
2. 将账号中心改成账号设置面板：突出资料、安全、连接与绑定三个职责区，删除和全局 `TopBar` 重复的页面头部。
3. 统一两个页面的布局、文案和交互基线，遵守 Ember 风格与 `docs/reference/web-design-guide.md`。

## 非目标

本次明确不做：

- 不改变后端 API、数据模型、数据库 schema 或权限逻辑。
- 不改变 Emby、Telegram、邮箱验证码、密码更新等业务语义。
- 不重做控制台全局导航、`TopBar`、`Sidebar` 或浮动帮助组件。
- 不引入新的前端设计系统、图标库或表单库。

## 当前事实

以当前代码和现行文档为准：

- 相关文档：
  - `docs/system-architecture.md`
  - `docs/reference/web-design-guide.md`
  - `docs/reference/plan-directory-governance.md`
  - `docs/plan/plan-template.md`
- 相关页面：
  - `services/web/src/views/console/DashboardView.vue`
  - `services/web/src/views/console/AccountCenterView.vue`
  - `services/web/src/components/console/RecentLibrarySection.vue`
  - `services/web/src/components/console/TopBar.vue`
  - `services/web/src/components/console/HelpWidget.vue`
- 概览页当前由大账号卡、独立过期告警、片库统计区和最近入库区组成，账号身份信息和服务状态混在同一层级。
- 账号中心当前由页面内头部、基本信息、安全设置、Telegram 绑定和弹窗组成；管理员 Emby 绑定操作嵌在“基本信息”的 `Emby ID` 字段里。
- `TopBar` 已经为 `console-dashboard` 和 `console-account` 提供页面标题与说明，因此页面内部不应再重复做大标题区。

## 方案设计

### 1. 概览页布局

概览页改为两段式：

1. 首屏状态网格：
   - 左侧：会员与服务状态，包含会员状态、到期时间和续费入口；不展示头像、用户名、角色或 Telegram 绑定状态。
   - 中间：Emby 入口，使用入口列表结构承载地址、复制、打开、配置/过期/未提供入口等边界状态；当前单地址渲染为一条“默认入口”，后续可自然扩展为多个地址。
   - 右侧：片库数字，展示电影、剧集、总集数三个紧凑指标。
2. 最近入库：
   - 保留 `RecentLibrarySection` 的全宽横向海报流。
   - 保留电影/剧集切换、刷新和横向滚动按钮。

过期状态只展示一次。普通用户过期时，在会员状态区和 Emby 入口区表达“需续费恢复访问”，不再额外插入一条独立红色告警条。

### 2. 账号中心布局

账号中心改为三段式：

1. 顶部紧凑状态摘要：
   - 展示头像、用户名、角色、会员状态、Telegram 状态。
   - 删除英文 `Account Center` eyebrow 和“回到概览”卡片。
2. 主体设置区：
   - 左列：基本资料与邮箱修改，包括用户名、邮箱、有效期、创建时间。
   - 右列：安全设置，包括当前密码、新密码、确认新密码和更新按钮。
3. 连接与绑定：
   - 将 Emby 关联/解除关联从“基本信息”中移出。
   - 将 Telegram 绑定、验证码、解绑操作和 Emby 绑定并列归入同一个“连接与绑定”区。

强制改密场景下，安全设置必须保留在首屏可见区域。必要时可在安全设置卡片顶部增加一条短 warning，不写长篇说明。

### 3. 视觉与交互基线

前端实现必须遵守 Ember 风格；设计与交互基线以 `docs/reference/web-design-guide.md` 为准。

- 页面背景继续使用 `bg-gray-50`，内容容器使用 `bg-white`。
- 主操作继续使用 `.btn-ember`；次操作使用白底描边。
- 页面文案按克制规则处理：标题、标签、按钮能表达清楚时，不额外补解释句。
- 卡片层级避免嵌套卡片；只有指标、状态块、表单区和连接项使用独立卡片。
- 状态不能只靠颜色表达，必须保留文本或图标。
- 可点击元素保留 `cursor-pointer`、hover 和 focus 态。

本次不存在偏离设计规范的特例。

## 关键流程

1. 读取当前页面状态：会员有效期、Emby 配置、媒体统计、Telegram 绑定状态。
2. 概览页按“服务状态 → Emby 入口列表 → 片库数字 → 最近入库”重排，不改变现有数据请求和错误处理语义。
3. 账号中心按“状态摘要 → 基本资料/安全设置 → 连接与绑定”重排，不改变邮箱、密码、Emby 绑定、Telegram 绑定的调用方法。
4. 调整重复文案、按钮层级和卡片样式，使两个页面和控制台其他页面保持一致。

## 失败路径与边界条件

- 用户已过期：概览页展示续费入口；Emby 入口展示锁定状态；不请求或不展示片库统计的误导性可用状态。
- Emby 未配置：管理员看到设置中心入口；普通用户看到系统配置中的中性提示。
- Emby 多入口：同一用户可见的多个入口按列表项展示，每项必须有名称、地址、复制和打开操作；当前接口仍只有单个 `embyUrl` 时按“默认入口”渲染。
- Emby 已配置但当前用户未绑定：最近入库区继续显示未绑定空态；账号中心连接区展示可处理的绑定状态。
- Telegram 未绑定：账号中心连接区展示生成绑定验证码入口；已绑定时展示当前 ID 和解绑操作。
- 邮箱域名白名单启用：保留现有前端提示和后端校验失败反馈。
- 强制改密：路由仍跳转到账号中心，安全设置在首屏可见，不被次要资料挤到页面下方。

## 影响范围

涉及的子系统：

- API：无。
- Web：有，涉及 `DashboardView.vue`、`AccountCenterView.vue`，可能少量触及现有控制台基础组件的使用方式。
- Bot：无。
- 配置/部署：无。
- 文档：实现完成后按实际稳定结论判断是否同步 `docs/reference/web-design-guide.md` 或 `docs/system-architecture.md`。如果只是页面局部布局调整，通常不需要同步系统架构文档。

## 验证方式

### 编译/测试

- `cd services/web && npm run build`
- 如改动触及现有账号中心行为或测试选择器：`cd services/web && npx vitest services/web/src/views/console/AccountCenterView.spec.ts`

### 手工验证

- 普通有效用户进入概览页：首屏能看到会员状态、Emby 入口、片库数字和最近入库。
- 普通过期用户进入概览页：续费入口明确，Emby 入口锁定，不出现重复红色告警。
- 管理员进入账号中心：能搜索并关联/解除 Emby 账号，位置在“连接与绑定”区。
- 未绑定 Telegram 用户进入账号中心：能生成绑定验证码；已绑定用户能看到 ID 并解绑。
- 邮箱修改、密码修改、邮箱验证码弹窗在桌面和移动端都不出现布局挤压。
- 移动端 375px、平板 768px、桌面 1440px 下无横向滚动和明显重叠。
